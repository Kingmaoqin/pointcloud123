## 一、环境准备

```bash
# 方式一（推荐）
conda env create -f environment.yml
conda activate patent_gap

# 方式二
pip install -r requirements.txt
```

> **ortools 必须锁定 9.10**，不得升级 —— 升级会改变开环 TSP 的解，使既有结果不可复现。

装好后先跑测试确认环境正确：

```bash
pytest tests/ -q          # 应为 128 passed，约 7 分钟
```

## 三、跑主实验（不需要任何外部数据）

```bash
# E7：规划环境先验强度消融，240 次运行
python scripts/run_e7_prior.py --out results/exp7

# E8：frontier 探索基线对照，144 次运行
python scripts/run_e8_frontier.py --out results/exp8

# 出图（四张曲线）
python scripts/plot_e7.py

# 核对文档中的数字与原始结果是否一致
python scripts/check_delivery_numbers.py
```

先跑冒烟测试确认链路通（各约 1–2 分钟）：

```bash
python scripts/run_e7_prior.py --quick --out results/exp7_smoke
python scripts/run_e8_frontier.py --quick --out results/exp8_smoke
```

## 四、四条必须遵守的运行纪律

### 4.1 版本守卫：不要把两个版本的结果拼在一起

每个 `run.json` 记录产出它的 `git_commit`。断点续跑时若发现盘上结果产自不同 commit，
脚本会直接 `SystemExit` 拒绝。

**要重跑请先清空对应输出目录**，不要在旧目录上续跑：

```bash
rm -rf results/exp7 && python scripts/run_e7_prior.py --out results/exp7
```

> 该守卫是在**三次"版本混合结果集"事故**之后加的。曾出现一批结果里 39 个产自
> commit A、31 个产自 commit B，而汇总表看不出任何异常。

### 4.2 实验写盘期间不要用 `git add -A`

会把中途的 partial `run.json` 扫进提交。提交实验产物须用**显式路径**，且在实验
**结束后**进行。

### 4.3 日志写到工作区外

否则 `git status` 非空，`git_commit` 会被记成 `<hash>-dirty`，失去可追溯性：

```bash
nohup python scripts/run_e7_prior.py --out results/exp7 > /tmp/e7.log 2>&1 &
```

### 4.4 共享 GPU / CPU 机器

本项目实验是**纯 CPU**（Embree 射线求交 ＋ A\*/距离场），不使用 GPU。在共享机上跑时
注意其他用户的负载 —— 实测负载 64 时单次运行由 40 s 涨到 180 s。

## 五、怎么读结果

### 5.1 输出结构

```
results/exp7/
├── {先验档}/{方法}/{场景}/{种子}/run.json    ← 单次运行的完整记录
├── summary.md                                ← 汇总表 + 配对置换检验 + Holm 校正
└── figs/*.png                                ← 曲线
```

### 5.2 单个 `run.json` 的字段

| 字段 | 含义 |
|---|---|
| `history[]` | 逐轮指标轨迹（每执行一站一条） |
| `final` | 最终指标 |
| `git_commit` / `config_hash` | 版本与配置指纹 |
| `status` | `ok` / `failed` |

### 5.3 主要指标（精确定义见专利包 `00B_术语与指标详解`）

| 指标 | 含义 | 注意 |
|---|---|---|
| `awc_gap_recovery` | 加权缺口恢复率，权重 `A_i·(1+λ_E·E_i)` | **不是纯面积加权**；会被大而平的表面主导 |
| `asset_recovery` | 资产级恢复率，构件内按权、**构件间等权** | 验收真正关心的量 |
| `crit_recall` | 关键设备召回（`E_i ≥ 0.8` 的缺口分块，阈值 `0.5·C_gt`） | 分块级，非构件级 |
| `vis_over` | 可见性**单向高估** `mean(max(预测−实际, 0))` | 本方法针对的错误是单向的 |
| `invalid_view_frac` | 无效视点占比（预测可见 ≥0.5 而实际 <0.1） | "白跑一趟"的直接计数 |
| `mplan_known_ratio` | M_occ 已确认栅格比例 | **这是探索类方法的目标**，不是本方法的 |
| `stop_reason` | `rounds` 正常 / `no_candidate` **需追查** | 大量 `no_candidate` 通常意味着有缺陷 |

### 5.4 统计口径

- 一个**配对** = 一个 `(场景, 种子)` 组合；E7/E8 均为 24 组配对
- 配对置换检验 ＋ **Holm 校正**；报告一律以 `p_holm` 为准
- **`p_holm = 1.0000` 不等于"两者相同"**，只表示这批数据没能显示出差别
- **同一指标的两个 p 值必须分清比较对象**：如地图覆盖，`B10 vs frontier` 为 0.0252，
  `B11 vs frontier` 为 0.1300 —— 不得互换

## 八、复现一个已有数字（推荐的自检方式）

```bash
python scripts/check_delivery_numbers.py
```

该脚本把文档里的 headline 数字回原始 `run.json` 重算，并**逐位复现汇总脚本的
Holm 检验族**（2 档 × 2 方法 × 10 指标 = 40 项）—— 检验族大小不同，`p_holm` 就不同，
这一点靠通读发现不了。全部通过时输出「全部通过」。
