## 一、B-1：q 的真实计算规则，以及应写 q_k 还是 q_{jk}

**【与代码不符 → 按代码改正】**

`viewpoints/ranking.py:242-258`：

```python
vis_front = frontality[visible_mask]          # dot(分块法向, 分块→相机方向), clip(0,1)
vis_dists = dists[visible_mask]               # 该候选视点到该分块形心的距离
dist_quality = np.exp(-((vis_dists - r_opt) ** 2) / (2 * sigma_d ** 2))
res_quality  = np.clip(1.0 / (1.0 + 0.15 * vis_dists), 0.0, 1.0)
q = vis_front * dist_quality * res_quality
```

**（1）符号必须是 q_{jk}，不是 q_k。**
`vis_front` 依赖第 k 个分块的法向**与**第 j 个视点的位置；`vis_dists` 是二者之间的
距离。**q 逐 (视点, 分块) 对计算，随 j 与 k 共同变化。** 初稿写 q_k 与实现不符。

**（2）q 的真实构成（可据实写入说明书）：**

| 因子 | 代码 | 含义 |
|---|---|---|
| 正视度 | `dot(n_k, dir_{k→j}).clip(0,1)` | 观测方向与分块法向的夹角余弦，取非负 |
| 距离质量 | `exp(−(d_{jk} − r_opt)² / (2σ_d²))` | 相对最佳扫描距离 r_opt 的高斯衰减 |
| 分辨率质量 | `clip(1/(1 + 0.15·d_{jk}), 0, 1)` | 随距离单调下降 |
| 有效量程 | 可见性门限 `d_{jk} ≤ max_range` | 超量程直接不计入 |

缺省值：`r_opt = 2.5 m`（显式给出时 `σ_d = 0.4·r_opt`，否则 `σ_d = 2.0`），
`max_range = 20 m`，`frontality_min = 0.35`，`fov_deg = 90`。

> 参数取值有一处必须一并说明（`ranking.py:146-157` 的注释）：σ_d 缺省保持 2.0 而
> 不随 r_opt 缩放，是因为多条调用通路未显式传 r_opt；若一并缩放，d = 6 m 处权重会
> 掉 99%。写入说明书时**不要**把 σ_d 写成恒等于 0.4·r_opt。

## 二、B-2：ρ_i 的真实计算、单位、期望密度、0/1 点边界

**【与代码不符 → 按代码改正】**

**（1）初稿的体密度在代码中不存在。**
初稿 [121]：「以最近邻距离 r 为球体半径，取球体体积的倒数」即 `1/(4πr³/3)`。
**全仓库没有任何一处这样计算密度。** 真实实现一律为**面密度**：

```python
# density/expected.py:52
rho_obs = n_points / max(areas, 1e-9)                      # 单位：点/m²
# closed_loop_v2.py:301
density_ratio = (n_pts / max(area, 1e-9)) / max(rho_req, 1e-9)
```

**（2）分块级聚合规则**：不存在"逐点局部密度再聚合"这一步。直接用
**该分块匹配到的点数 ÷ 该分块面积**，无需平均或中位数。

**（3）期望密度 ρ̂ 不是全局常数**（`density/expected.py:39-42`）：

```python
def rho_required(importance, rho0, lambda_e):
    """公式(33) 右式: ρ_req = ρ_0(1+λ_E·E_i)。"""
    return rho0 * (1.0 + lambda_e * np.clip(importance, 0, 1))
```

即 **ρ̂_i = ρ0·(1 + λ_E·E_i)**，随分块所属构件的工程重要度 E_i 变化。
单位与 ρ_i 同为 **点/m²**，量纲自洽。

**（4）0 点边界**：`max(area, 1e-9)` 防零除；`n_points = 0` 时 `rho_obs = 0`，
`density_ratio = 0`，密度项取满值 1。**代码不区分"0 点"与"1 点"**，无特殊分支。

**建议改法**：把初稿 [121] 的体密度整段**删除**，改为：

> 三维点云在表面分块上的点云密度取该表面分块所匹配的采样点数量与该表面分块面积
> 之比，单位为点/平方米；所述期望密度按该表面分块所属构件的工程重要度确定，
> 即 ρ̂_i = ρ0·(1 + λ_E·E_i)，其中 ρ0 为基准期望密度，λ_E 为重要度系数。

## 三、B-3：C_i 是三角面数量比例还是面积比例

**【代码中无 → 初稿写法应删除；且有一处必须处理的相关性问题】**

**（1）「被覆盖三角面数量 / 分块总三角面数量」在两条代码路径中都不存在。**

- **仿真路径**（`closed_loop_v2.py:208-218`）：
  `C_i = 该分块采样点中被任一已执行站观测到的比例`（对分块表面均匀撒点后按射线可见
  性统计），是**采样点比例**，不是三角面比例。
- **真实点云路径**（`evidence/__init__.py:407-409`）：

```python
est_density  = est_count / max(area, 1e-6)
density_ratio = clip(est_density / ref_density, 0.0, 1.5)
# Coverage ratio: proxy from density ratio (no per-patch surface sampling needed)
coverage_ratio = float(np.clip(density_ratio, 0.0, 1.0))
```

**（2）必须处理的相关性问题。** 在真实点云路径上 `C_i` 是 `density_ratio` 的**代理**，
于是初稿的

```
G_i = α·(1 − C_i) + β·max(0, 1 − ρ_i/ρ̂)
```

两项**是同一个量**，公式退化为 `G_i = (α+β)·(1 − clip(ρ_i/ρ̂, 0, 1)) = 1 − clip(...)`。
**α 与 β 完全不起作用。**

这与初稿 [127][128] 主张的「α、β 分别控制扫描广度与强度，可按应用需求调整」
**直接矛盾** —— 在真实点云路径上该调节能力并不存在。

**三条可选处理（请研发方选定）**：

1. 说明书明确限定：C_i 与 ρ_i 须由**相互独立**的两条统计得到（如 C_i 由分块表面
   均匀采样点的观测比例得到，ρ_i 由点数/面积得到），并按仿真路径的做法实现真实
   点云侧的独立覆盖率统计；
2. 若短期内无法实现独立统计，则**删去 α/β 可调这一效果主张**，只保留单项；
3. 保留两项但在说明书中如实写明：当覆盖率由密度比代理时二者退化为一项。

**不建议**沿用初稿现文字 —— 它主张了一个当前实现给不出的技术效果。

**（3）另一处口径问题**：初稿把两项式称作"缺口分数 G_i"，而代码中该两项式是
`D_geo`（六项证据之一，`gap/scoring.py:205-212`，权重恰为 **0.60 / 0.40**）；
代码真正的 `G_gap` 是 D_sem / D_mat_missing / D_mat_conflict / D_obs / D_ang / D_geo
六项的归一化加权和（`scoring.py:242`）。
请研发方确认初稿是**有意简化为单一几何证据**，还是应当写成六项证据体系。

## 四、B-4：S22–S23 的真实区域生长循环与第一法向约束的比较对象

`patches/__init__.py:56-81` 全文如下（这是唯一实现）：

```python
def _region_grow(local_normals, adj, cos_threshold):
    labels = np.full(n, -1); patch_id = 0
    for start in range(n):                        # ← 逐个未归属三角面作种子
        if labels[start] >= 0: continue
        queue = [start]; labels[start] = patch_id
        seed_normal = local_normals[start]
        while head < len(queue):
            cur = queue[head]; head += 1
            ref_n = local_normals[cur]            # ← 当前已归属的那个面
            for nb in adj[cur]:
                if labels[nb] >= 0: continue
                if (dot(ref_n, local_normals[nb]) >= cos_threshold
                        and dot(seed_normal, local_normals[nb]) >= cos_threshold):
                    labels[nb] = patch_id; queue.append(nb)
        patch_id += 1
```

| 第一约束：候选面与「任一相邻**候选**面」 | `dot(local_normals[cur], nb)`，`cur` 是**当前正在向外扩展的、已归属本分块**的三角面 | **【与代码不符】** 应改为「与当前表面分块中和该候选三角面相邻的**已纳入**三角面」 |

## 五、B-5：等距最近三角面的确定性选择规则

**【代码已实现且更强 → 初稿「任一个」应改正】**

初稿 [116]：「该采样点仅与其中**任一个**表面分块相匹配」。

代码中**已有完整的确定性规则**，且是 2026-07-31 应合作方疑问 2 专门加入的
（`data/tie_break.py`，并由 `pointcloud.py:118-124` 调用）：

> 规则（逐级适用直至唯一）：
> **第一级** 取最近距离最小者（并列判定含数值容差 tol = 1e-6 m）；
> **第二级** 取"由该三角面上最近表面点指向该点的方向"与该三角面法向所成夹角的
> **余弦绝对值最大者**（取绝对值使判定不受顶点绕序影响）；最近距离为零时该方向
> 无定义，视为本级并列，进入第三级；
> **第三级** 取"三个顶点坐标按字典序排序后所得序列"在**字典序上最小者**；
> **第四级** 仅当两三角面几何完全重合时适用 —— 按所属构件标识（如 IFC GlobalId）择一。

第三级采用**几何量而非存储索引**，因此结果不依赖三角面在文件中的存储顺序。
`tests/test_tie_break.py` 实测：若第三级改用"索引最小者"，同一等距点在 **24 种三角面
排列**下会被判给不同分块；改用几何字典序后 24 种排列**全部给出同一归属**。

**初稿写「任一个」是相对已有实现的倒退**，且会被指出保护范围不确定。应按上述规则写入
（这是真实实现，不属补造），并说明其"与存储顺序无关"的效果 —— 这一条本身就有可主张的
技术效果。

## 六、S3 关联粒度：一处初稿与实现的实质性不一致

**【与代码不符 → 需研发方决定如何处理】**

初稿 S3：「将各所述采样点分别与**至多一个所述表面分块**相匹配」。

代码真实（`data/pointcloud.py:127-134`）：关联输出的是 **构件级**字段 ——
`element_index` / `element_guid` / `ifc_class`，**没有 patch_id**。
分块级的点数是在 `evidence/__init__.py:383-386` 中**按面积比例摊派估算**得到的：

```python
area_ratio = area / total_elem_area          # 该分块面积 / 该构件总面积

```

即：**点实测关联到构件；分块级点数是按面积比例估算的，不是逐点统计的。**

这直接影响 C_i 与 ρ_i 的性质 —— 二者都建立在估算点数之上。若权利要求写"采样点与
表面分块相匹配"，而实现只做到构件级，会构成说明书未充分公开支持该权利要求的风险。

**两条处理路径（请研发方选定）**：

1. 按实现如实写成两步：先将采样点匹配到构件，再按分块面积比例分配至各表面分块；
2. 若确需分块级实测匹配，需先补实现（`triangle_patch_map` 已存在于
   `patches/__init__.py:240`，具备做到分块级的条件），验证后再写。

12. **C_i 与 ρ_i 在真实点云路径上完全相关**，α/β 可调这一效果主张当前不成立（§三）

14. **初稿两项式对应代码的 D_geo 一项证据**，而代码的 G_gap 是六项加权 —— 确认是否有意简化（§三）
15. **S4 目标分块：单个最高 vs 阈值筛出一批**（§七）

## 九、一句总评

修订版「不得为写专利而补造算法」的原则完全正确，本次核实**没有**推翻这一原则 ——
