# 00B 术语与指标详解

本包中出现的每一个代号、术语、指标都在此定义。**建议先通读本文件再读 01–08。**

每个指标除定义外，都写明「它**不**代表什么」—— 多数误读来自这一栏。

---

## 一、两个模型（本轮工作的核心概念）

改造前，规划器用的是**一份**几何：设计模型。它同时被用来回答两个完全不同的问题。
本轮把它拆成两个。

### 目标参考模型（M_ref）

**回答：我要检查什么。**

内容：待检查的目标构件清单、目标表面几何、工程属性（重要度、点密度要求、是否带电）。

- 作业前给定，全程不变。
- **必须完整描述目标表面** —— 没有它就没有「缺口」这个概念。
- **不要求描述现场其他东西**（厂房、围墙、堆放物、施工车辆）。

### 规划环境模型（M_plan）

**回答：规划器当前认为现场哪里能走、什么会挡住视线。**

M_plan **不是单一表示**，它由两个逻辑子部分组成，二者的信息来源并不相同：

```
M_plan = { M_occ , M_vis }
```

| 子部分 | 内容 | 用于 | 初始内容来自 | 如何更新 |
|---|---|---|---|---|
| **M_occ**（占据/通行侧） | 平面三态栅格 ＋ 安全禁入约束 | 可通行判断、路径代价 | **初始扫描的实测点云**（＋允许写入的安全禁入约束） | 每执行一站，用新增点云按同一规则并入 |
| **M_vis**（遮挡/可见性侧） | 用于射线求交（first-hit）的三角网 | 可见性预测、覆盖成功概率 | **M_ref 的目标表面 ＋ 当前实现固定保留的基础几何（地面）＋ 该先验档允许提供的部分已知环境构件** | 每执行一站，把 S7a 发现的占据几何并入 |

> **这一点必须准确，不能简化：**
> **M_occ 的通行占据状态主要由实测观测建立并逐轮更新；而 M_vis 的初始内容至少包含
> M_ref 的目标表面与固定保留的基础几何，并可结合当时允许的已知环境先验，再由新增
> 观测更新。**
>
> 因此**不得**写成「M_plan 完全由点云建立」——那对 M_vis 不成立。

### 三者关系（不要读错）

- **M_ref ≠ M_plan**：前者定义"要检查什么"，后者描述"现在知道现场什么样"。
- **但 M_ref 的目标几何是 M_vis 的一部分**：目标构件本身就会挡住视线，把它排除在
  遮挡模型之外在物理上讲不通。
- 因此**既不能**说「M_plan 不使用 M_ref」，**也不能**说「M_plan 就是 M_ref」。

### 一条必须成立的约束

> **凡 M_ref 声明为目标的表面，M_vis 的初始内容必须包含其几何。**

否则会出现「要求扫一栋楼，却没给这栋楼的几何」——规划器求交时会以为自己能透视过去。
先验强度只允许调节**非目标**环境几何。本轮曾出现过违反这条的状态，已修复并加了测试
（`test_every_target_surface_is_present_in_the_planning_model`）。

### 代码中的对应

本轮只做概念定义澄清，**未重命名代码变量** **[C]**。对应关系：

| 概念 | 代码 |
|---|---|
| M_occ | `SimWorld.env`（`PlanningEnvGrid`） |
| M_vis | `SimWorld.plan_oracle`（初始内容由 `SimWorld.ref_tris` 决定） |
| M_ref 的目标表面 | `world.patches` / `tri_to_patch >= 0` 的三角面 |

## 二、场景与几何术语

| 术语 | 含义 |
|---|---|
| **构件**（component / element） | 一个独立的物体。合成变电站里是一台断路器、一段母线、一栋厂房；真实 IFC 里是一个 `IfcWall`、`IfcColumn` 等 |
| **表面分块**（patch） | 把一个构件的表面按法向连续性区域生长切成的小片。是缺口检测、覆盖率计算的最小单位。一个 S/low 场景约 484 个分块 |
| **目标构件** | 本次验收要检查的资产（断路器、隔离开关、CT/PT、避雷器、变压器、母线、绝缘子、构架） |
| **非目标环境构件** | 遮挡视线、影响通行但不检查的东西（厂房、围墙、杂物）。代号 `ENVIRONMENT_CLASSES` |
| **竣工态临时占位物** | 施工车辆、料堆、脚手架。**设计模型中根本不存在**（`in_bim=False`），但实际会挡住扫描仪。实验参数 `n_temp` 控制其数量 |
| **设计几何 vs 竣工实景几何** | 前者是规划器能看到的；后者是仿真器用来生成"扫描仪实际测到什么"的。二者必须分开，否则"遮挡预测错了没有"无法测量 |

### 为什么变电站里"非目标环境"很少

按三角面计，厂房 + 围墙 + 杂物只占 **3.6–5.3%**。原因是：**变电站里挡住设备的主要是
其他设备，而设备本身就是目标**。这条领域事实贯穿全部结论 —— 它意味着 M_ref 天然就
提供了大部分遮挡体，所以"遮挡侧的先验"本就不像看上去那么强。

**因此本包中所有关于"拿掉环境先验的代价"的数字，都不得外推到非目标环境更多的场景**
（如市政道路、厂房内部）。

## 三、缺口相关

| 术语 | 含义 |
|---|---|
| **缺口**（gap） | 某个目标表面分块没被扫够 —— 点太少、密度不达标、角度不好，或压根没扫到 |
| **缺口证据** | 由实测点云算出的、描述某分块"缺到什么程度"的一组量 |
| **G_gap** | 缺口分数。超过阈值 τ_gap 的分块被判为"缺口表面分块" |
| **G_task** | 任务分数。缺口程度 × 工程重要度 —— 一台断路器的缺口比一段围墙的缺口更该补 |
| **覆盖成功概率** | 某个候选站位对某个分块，综合可见性与观测质量（距离、入射角、密度）后，"能把它补上"的概率 |
| **ρ_req / ρ0** | 点密度要求 / 密度标定基准（本轮取 50） |

## 四、M_plan 占据侧的三种状态

| 状态 | 含义 | 处置 |
|---|---|---|
| **已确认占据**（OCCUPIED） | 观测到回波点，且高度落在平台通行高度带 `[0.20, 1.80] m` 内 | 障碍 |
| **已确认自由**（FREE） | 站位到某个回波点的连线经过此处 | 可通行 |
| **未确认**（UNKNOWN） | 没有任何证据 | **不作为可通行区域** |

几个关键点：

- **自由状态来自射线穿越，而非来自"模型里此处为空"。** 但必须准确理解其物理含义：
  当前实现把**全部**回波点（不限高度）的射线**按 XY 投影**标记沿途栅格为自由，
  不考虑射线高度随距离的变化。因此一条从 2.0 m 高的三脚架掠过 1.0 m 障碍上方的射线，
  也会把该障碍所在栅格标为自由。
  > 准确表述应为：**将射线穿越区域作为自由空间的观测证据，并在当前二维栅格实施方式
  > 下据此更新 FREE 状态**。该状态是**基于二维投影的规划近似**，最终仍受平台半径收缩、
  > 已确认占据优先以及安全禁入区约束。**不得**写成"证明该位置可通行"。
  >
  > 自限机制与实测量级：同一物体通常也会在通行高度带内产生回波而被标为占据，占据
  > 优先且不被抹回。实测（S/low seed0，P0，初始三站后）"M_plan 说能走、实景不能走"
  > 的栅格占 M_plan 可通行的 **1.41%**，而反方向（保守地判为不能走）占 **14.31%** ——
  > 该实现整体偏保守。详见 `09_剩余代码逻辑核查_FINAL.md` 核查二。**[A]**
- **占据不被后续射线抹回自由** —— 占据的证据强于穿越的证据。
- **未知不当作可通行**，这是弱先验下最容易"偷跑"的一处。代码里由 `unknown_is_free`
  显式控制，缺省为 False。
- **平台半径膨胀**：算出的自由区还要按平台半径（0.6 m）向内收缩，因为平台不是一个点。
- **平台站过的位置**：平台确实在那里架过站，说明那里装得下平台 —— 这是比"射线穿过"
  更强的证据，不被膨胀抹掉。**但已确认占据的格除外**（观测更近）。
  > 这一条不是锦上添花：不加它会出现"平台被卡在自己正站着的位置上"，随后从该处出发
  > 的距离场处处为无穷、全部候选被判不可达、任务提前终止。见 03 文档第 4.4 节。
- **带电体禁入区**：唯一允许的"无观测先验"。它是**作业安全规程**而非现场几何，与是否
  扫描无关，且只增加禁入、不增加可通行。
- **frontier 栅格**：已确认自由、且四邻域中存在未确认的格 —— 即"已知区与未知区的
  边界"。探索类方法就是往这里走。

| 代号 | 含义 |
|---|---|
| **B10_full** | 本方法的完整价值函数（公式 26–45），**不开**在线环境更新。先验给多少就是多少，全程不改 |

## 六、五个先验强度档（E7 的自变量）

这是 E7 唯一变化的东西。**看懂这张表，E7 的结论就看懂了。**

| 档 | 遮挡侧（看得见什么） | 占据侧（能走到哪） | 这一档单独回答什么 |
|---|---|---|---|
| **LEGACY** | 完整参考模型 | 完整模型栅格化 | 原方案，参照基准 |
| **P100** | 完整参考模型 | **由观测建立** | 「把'哪里能走'改成观测驱动，要付多少代价」 |
| **P75** | 目标 ＋ 随机保留 75% 环境构件 | 由观测建立 | 遮挡先验减弱的代价 |
| **P50** | 目标 ＋ 随机保留 50% 环境构件 | 由观测建立 | 同上 |
| **P0** | **不提供额外非目标环境构件**（目标表面与地面仍在） | 由观测建立 | 同上，最弱 |

两点务必注意：

1. **`LEGACY → P100` 与 `P100 → P0` 必须分开看。** 它们是两条不同的信息通路
   （**能不能走** / **看不看得见**）。混在一档里，读不出是哪一条在起作用。
2. **环境构件按对象整取整舍**，不按三角面随机删 —— 随机删三角面会留下"半张皮"，
   物理上无意义。目标构件与地面在任何档都保留。

## 七、指标详解

以下 `↑` 表示越大越好，`↓` 表示越小越好。

### 7.0 全部指标的共同基础（先看这一段）

实现位置：`src/patent_gap/simulation/closed_loop_v2.py::episode_metrics()` **[A]**

| 符号 | 代码 | 含义 |
|---|---|---|
| `A_i` | `p["area"]` | 分块 i 的面积 |
| `E_i` | `p["engineering_importance"]` | 分块 i 的工程重要度，∈[0,1] |
| `C_gt[i]` | `gt["C_gt"]` | **参考站集**（8 m 网格撒满、剔除禁入区）对分块 i 能达到的覆盖率 |
| `C_init[i]` | `gt["C_init"]` | 初始扫描对分块 i 的覆盖率 |
| `C_now[i]` | `obs.coverage()` | 当前（含本轮补扫）对分块 i 的覆盖率 |
| `y[i]` | `gt["y"]` | **缺口判定**：`y = C_init < 0.5·C_gt` |

两个派生量：

```
rec[i] = clip( (C_now[i] − C_init[i]) / max(C_gt[i] − C_init[i], 1e−9), 0, 1 )   # 单分块恢复度
w[i]   = A_i · (1 + λ_E · E_i)                    # 权重, λ_E = lambda_e = 1.0
```

> **注意 `w` 不是纯面积**，而是 **面积 ×(1＋重要度)**。本文件早前版本误写为"按面积
> 加权"，已按代码更正。

### 7.1 任务完成度

#### `awc_gap_recovery` 加权缺口恢复率 ↑

```
awc = Σ_{i∈缺口} rec[i]·w[i]  /  Σ_{i∈缺口} w[i]
```

- **统计单位**：**分块**。只统计 `y[i]` 为真的缺口分块。
- **权重**：`A_i·(1+E_i)` —— 面积占主导（面积跨约 200 倍，`1+E_i` 只跨 1.0–2.0）。
- **范围**：0–1。`y` 全假时为 `nan`。
- **不代表**：不代表"资产被检查到的比例"。一段大面积母线的分块权重可能是一台断路器
  的几十倍，所以该指标仍会被大而平的表面主导。

#### `asset_recovery` 资产级恢复率 ↑

```
对每个含缺口的构件 g：  s_g = Σ_{i∈g∩缺口} rec[i]·w[i] / Σ_{i∈g∩缺口} w[i]
asset_recovery = mean_g( s_g )
```

- **统计单位**：**构件**（`element_guid`）。
- **关键区别**：**构件内**按 `w` 加权，**构件之间等权**（简单算术平均）。
- **范围**：0–1。无缺口构件时为 `nan`。
- **为什么必须单独报**：实测 S/low 上 4 个主变面 ＋ 5 个建筑面就占了 awc 权重的 92%，
  十几个断路器/互感器合计不到 4% —— 一个只刷大平面的方案能拿到很高的 awc。验收关心
  的是"每个资产是否都扫到了"。

#### `crit_recall` 关键设备召回 ↑

```
crit = y & (E_i ≥ 0.8)
crit_recall = mean( C_now[crit] ≥ 0.5 · C_gt[crit] )
```

- **统计单位**：**分块**（不是构件）。
- **阈值**：当前覆盖率达到**参考站集可达覆盖率的一半**即计为"已补上"。该 0.5 与缺口
  判定 `y = C_init < 0.5·C_gt` 使用同一门槛。
- **哪些算关键**：`E_i ≥ 0.8` 的缺口分块（隔离开关、CT/PT、断路器等）。
- **范围**：0–1。

#### `dens_ok` 密度达标率 ↑ / `dens_ok_vs_full` ↑

```
ρ_req[i] = ρ0 · (1 + λ_E · clip(E_i,0,1))            # 公式(33), ρ0 = 50
dens_ok  = mean_i( n_pts[i]/A_i ≥ ρ_req[i] )         # 对**全部**分块, 不只缺口分块
dens_ok_vs_full = dens_ok / ref,  ref 为用参考站集点数按同式算得的达标率
```

- **统计单位**：**全部分块**（注意：与 awc/asset 不同，不限于缺口分块）。
- `dens_ok_vs_full` **可以大于 1**（比参考站集做得还好），不是错误。

| 指标 | 含义 | 说明 |
|---|---|---|
| `path_len_m` ↓ | 移动平台走过的路径总长（米） | **预算口径是纯路径长度**。单站架设耗时只在贪心的性价比里折算成等效距离，不占这个预算 |

### 7.3 预测质量（本轮新增，E7/E8 的关键证据）

这三个量在**每执行一站时**测量，用的是**规划器当时实际据以决策的那个遮挡模型**，
在该站观测并入之前计算。也就是说，它们衡量的是"规划器当时以为看得见的，和实际
看得见的，差多少"。

#### `vis_mae` 可见性预测平均绝对误差 ↓

`mean( |预测可见比例 − 实际可见比例| )`，对全部目标分块取平均。双向。

#### `vis_over` 可见性**单向高估** ↓ ← **最重要的一个**

`mean( max(预测 − 实际, 0) )`。

- **为什么单独看单向**：本发明针对的错误是**单向的** —— 模型里没有的物体只会挡住
  真实扫描，不会挡住预测。把它和低估的一侧混在 MAE 里，会被稀释。
- 实测中 B10 的 `vis_mae` 与 `vis_over` 数值相同，说明误差**几乎全部是高估**。

#### `invalid_view_frac` 无效视点占比 ↓

预测明确可见（≥0.5）而实际几乎全被挡住（<0.1）的目标分块占比。
这是**"白跑一趟"的直接计数口径** —— 规划器以为能测到，去了发现被挡住。

### 7.4 建图进度

#### `mplan_known_ratio` 规划环境模型已确认比例 ↑

实现：`PlanningEnvGrid.known_ratio()` = `mean(state != UNKNOWN)` **[A]**

- **统计单位**：**M_occ 的二维栅格**（分辨率 0.25 m），覆盖整个场地包围盒。
- **这是探索类方法的目标函数**，不是本方法的。
- LEGACY 档恒为 1.000：该档不使用 `PlanningEnvGrid`，规划器一开始即持有完整地图，
  按定义已知率为 1（代码中直接写入 1.0，非测量值）。**[A]**

### 7.5 终止原因 `stop_reason`

| 值 | 含义 |
|---|---|
| `rounds` | 正常用满全部轮次 ← **健康状态** |
| `stations` | 触及站数上限 |
| `length` | 路径预算耗尽 |

## 八、统计方法

### 什么是一个"配对"

一个 **(场景, 种子)** 组合。E7 用 3 类场景 × 8 个随机种子 = **24 组配对**。
比较两个方法时，是在**同一个场景、同一个随机种子**下比，消除场景难度的影响。

### 配对置换检验（paired permutation test）

- **做什么**：把 24 组差值的符号随机翻转，看"实际观察到的平均差"在随机翻转的分布里
  有多极端。
- **p 值的含义**：若两个方法真的没差别，"看到这么大的差"的概率。**p 小 = 差别不像是
  偶然**。
- **分辨率下限**：m 组配对能给出的最小 p 是 `2/2^m`。24 组时是 1.2×10⁻⁷，足够。

### Holm 校正与 `p_holm`

同时做多个检验时，"总有一个碰巧显著"的概率会累积。Holm 校正逐步抬高门槛来抵消。

- **`p_holm` 是校正后的 p 值**，比原始 p 大或相等。本包中报告的显著性一律以它为准。
- **`p_holm = 1.0000` 不等于"两者相同"**，只等于"这批数据没能显示出差别"。

### bootstrap 95% 置信区间

对差值重采样 10000 次得到的区间。**若区间不跨 0，方向是稳的。**

### 怎么读一行结果

表中一行形如：先验档 `P0`，指标 `asset_recovery`，差值 `+0.092`，
95% 置信区间 `[+0.042, +0.146]`，`p_holm` = `0.0117`。

读作：在 P0 档，B11 的资产恢复率比 B10 平均高 **0.092**；重采样 95% 的情况下这个
差在 +0.042 到 +0.146 之间（**不跨 0，方向稳**）；多重比较校正后 p = **0.0117**
（**显著**）。

## 九、可复现性与工程约定

| 术语 | 含义 |
|---|---|
| **`run.json`** | 一次运行的全部记录：逐轮指标轨迹、最终指标、配置哈希、**产出它的 git commit** |
| **commit 守卫** | 断点续跑时若发现盘上结果产自不同 commit，直接报错退出。此机制是在**三次"版本混合结果集"事故**之后加的 |
| **`config_hash`** | 实验配置的哈希。配置变了哈希就变 |

| **种子**（seed） | 控制场景生成与仿真随机性。同一种子必然复现同一结果 |

### Oracle leakage（"偷看答案"）

**定义**：规划器读到了真实现场**不可能提供**给它的信息。

判据不是"读没读完整模型"，而是「**作业当天，这条信息拿不拿得到**」。

- ❌ 泄漏：规划器绕开了一辆设计模型里根本查不到的施工车辆。
- ✅ 不是泄漏：仿真器用完整竣工几何生成"扫描仪实际测到什么"——那是被测量的现实本身
  （Simulator Truth），且它不进入任何规划决策。

完整清单见 `06_Oracle_Leakage_Audit_FINAL.md`。

## 十、三个容易混淆的地方

### 10.1 "地图覆盖得快" ≠ "任务缺口补得好"

`mplan_known_ratio` 是探索类方法的目标；`asset_recovery` 是本方法的目标。
E8 中 frontier 在前者上**赢**、在后者上差 0.40。**两个轴必须一起报**，不得只报
对自己有利的那个。

### 10.2 "可见性误差改善" ≠ "恢复率改善"

这是**分开检验的两件事**。在线环境更新后，各先验档的可见性单向高估**均不高于 0.002**
（实测 0.001–0.002）
（p_holm 全为 0.0020），但它对**恢复率**的增益只在 P0 档达到显著（p_holm 0.0117），
P100/P75/P50 三档分别为 0.47 / 0.14 / 0.09。**不得把前者的显著性挪用给后者。**

### 10.3 E7 与 E2/E5/E6 的绝对指标不可跨实验比较

本轮统一了目标集口径（厂房、围墙、杂物不再算作待扫目标，占分块数的 5.7–8.0%）。
因此 E7/E8 与更早的 E2/E5/E6 的**绝对数值**不可直接对比。**各实验内部的对照不受
影响**，且 commit 守卫会拦住把两种口径拼在一起的续跑。既有结果全部原样保留在盘上。

### 10.4 本实验是"已有初始扫描之后的补扫"，不是从零开始的自主探索

**这是本轮结论最重要的适用边界。**

实测：P0 条件下，**仅初始三站扫描之后**，M_occ 的已确认栅格比例已达
**0.893**（12 个场景/种子组合，范围 0.814–0.950）**[A]**；补扫过程再把它推到 0.949。

因此 E7 证明的是：

> 在**已经完成初始扫描、并由初始扫描获得较丰富通行观测**的补扫阶段，不需要额外用
> 完整设计模型生成通行地图。

它**没有**证明：

> 机器人可以从几乎完全未知的环境开始自主探索。

这与另一条边界完全一致：**本发明不解决"完全无信息时如何选择第一站"**——初始站位是
作业输入（现场记录的实际架站位置），不由本方法推出。

### 10.5 E8 只直接对照了 frontier 探索基线，不是 NBV/SLAM 基准测试

E8 实现并实测的是 **frontier-based exploration** 一种基线。**未**实测：
learning-based NBV、reconstruction NBV、uncertainty-based NBV、现代 active SLAM 基准。

- 可以写：本方法与 SLAM / frontier / NBV 在**任务定义与收益函数层面**存在区别。
- 若写"实验表明"，必须限定：**E8 直接实验比较的是 frontier-based exploration**。
- **不得**据此声称优于所有 NBV 或 SLAM 方法。
