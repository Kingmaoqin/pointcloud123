# 00B 术语与指标详解

本包中出现的每一个代号、术语、指标都在此定义。**建议先通读本文件再读 01–08。**

每个指标除定义外，都写明「它**不**代表什么」—— 多数误读来自这一栏。

---

## 一、两个模型（本轮工作的核心概念）

改造前，规划器用的是**一份**几何：设计模型。它同时被用来回答两个完全不同的问题。
本轮把它拆成两个。

### 目标参考模型（M_ref）

**回答：我要检查什么。**

内容：待检查的目标构件清单、目标表面几何、工程属性（重要度、点密度要求、是否带电）。

- 作业前给定，全程不变。
- **必须完整描述目标表面** —— 没有它就没有「缺口」这个概念。
- **不要求描述现场其他东西**（厂房、围墙、堆放物、施工车辆）。

### 规划环境模型（M_plan）

**回答：现场哪里被占据，什么挡住视线。**

内容分两侧：

| 侧 | 内容 | 用途 |
|---|---|---|
| **占据侧** | 平面三态栅格 | 判断移动平台能不能走、路径多长 |
| **遮挡侧** | 用于射线求交的三角网 | 预测某个站位能看到哪些目标表面 |

- **由实测点云建立**，每扫一站更新一次。
- **不要求完整**。没观测到的地方就是"未确认"。

### 一条必须成立的约束

> **凡 M_ref 声明为目标的表面，M_plan 的初始内容必须包含其几何。**

否则会出现「要求扫一栋楼，却没给这栋楼的几何」——规划器求交时会以为自己能透视过去。
先验强度只允许调节**非目标**环境几何。本轮曾出现过违反这条的状态，已修复并加了测试。

## 二、场景与几何术语

| 术语 | 含义 |
|---|---|
| **构件**（component / element） | 一个独立的物体。合成变电站里是一台断路器、一段母线、一栋厂房；真实 IFC 里是一个 `IfcWall`、`IfcColumn` 等 |
| **表面分块**（patch） | 把一个构件的表面按法向连续性区域生长切成的小片。是缺口检测、覆盖率计算的最小单位。一个 S/low 场景约 484 个分块 |
| **目标构件** | 本次验收要检查的资产（断路器、隔离开关、CT/PT、避雷器、变压器、母线、绝缘子、构架） |
| **非目标环境构件** | 遮挡视线、影响通行但不检查的东西（厂房、围墙、杂物）。代号 `ENVIRONMENT_CLASSES` |
| **竣工态临时占位物** | 施工车辆、料堆、脚手架。**设计模型中根本不存在**（`in_bim=False`），但实际会挡住扫描仪。实验参数 `n_temp` 控制其数量 |
| **设计几何 vs 竣工实景几何** | 前者是规划器能看到的；后者是仿真器用来生成"扫描仪实际测到什么"的。二者必须分开，否则"遮挡预测错了没有"无法测量 |

### 为什么变电站里"非目标环境"很少

按三角面计，厂房 + 围墙 + 杂物只占 **3.6–5.3%**。原因是：**变电站里挡住设备的主要是
其他设备，而设备本身就是目标**。这条领域事实贯穿全部结论 —— 它意味着 M_ref 天然就
提供了大部分遮挡体，所以"遮挡侧的先验"本就不像看上去那么强。

**因此本包中所有关于"拿掉环境先验的代价"的数字，都不得外推到非目标环境更多的场景**
（如市政道路、厂房内部）。

## 三、缺口相关

| 术语 | 含义 |
|---|---|
| **缺口**（gap） | 某个目标表面分块没被扫够 —— 点太少、密度不达标、角度不好，或压根没扫到 |
| **缺口证据** | 由实测点云算出的、描述某分块"缺到什么程度"的一组量 |
| **G_gap** | 缺口分数。超过阈值 τ_gap 的分块被判为"缺口表面分块" |
| **G_task** | 任务分数。缺口程度 × 工程重要度 —— 一台断路器的缺口比一段围墙的缺口更该补 |
| **覆盖成功概率** | 某个候选站位对某个分块，综合可见性与观测质量（距离、入射角、密度）后，"能把它补上"的概率 |
| **ρ_req / ρ0** | 点密度要求 / 密度标定基准（本轮取 50） |

## 四、M_plan 占据侧的三种状态

| 状态 | 含义 | 处置 |
|---|---|---|
| **已确认占据**（OCCUPIED） | 观测到回波点，且高度落在平台通行高度带 `[0.20, 1.80] m` 内 | 障碍 |
| **已确认自由**（FREE） | 站位到某个回波点的连线经过此处 | 可通行 |
| **未确认**（UNKNOWN） | 没有任何证据 | **不作为可通行区域** |

几个关键点：

- **"射线穿过 = 自由"是唯一能由观测*证明*某处可通行的依据。** 激光打到那个回波点才
  停下，沿途必然是空的。
- **占据不被后续射线抹回自由** —— 占据的证据强于穿越的证据。
- **未知不当作可通行**，这是弱先验下最容易"偷跑"的一处。代码里由 `unknown_is_free`
  显式控制，缺省为 False。
- **平台半径膨胀**：算出的自由区还要按平台半径（0.6 m）向内收缩，因为平台不是一个点。
- **平台站过的位置**：平台确实在那里架过站，说明那里装得下平台 —— 这是比"射线穿过"
  更强的证据，不被膨胀抹掉。**但已确认占据的格除外**（观测更近）。
  > 这一条不是锦上添花：不加它会出现"平台被卡在自己正站着的位置上"，随后从该处出发
  > 的距离场处处为无穷、全部候选被判不可达、任务提前终止。见 03 文档第 4.4 节。
- **带电体禁入区**：唯一允许的"无观测先验"。它是**作业安全规程**而非现场几何，与是否
  扫描无关，且只增加禁入、不增加可通行。
- **frontier 栅格**：已确认自由、且四邻域中存在未确认的格 —— 即"已知区与未知区的
  边界"。探索类方法就是往这里走。

## 五、方法代号

| 代号 | 含义 |
|---|---|
| **B10_full** | 本方法的完整价值函数（公式 26–45），**不开**在线环境更新。先验给多少就是多少，全程不改 |
| **B11_disc** | B10 ＋ **在线环境更新**。每扫一站，从新点云中识别"测到了但参考模型里没有"的表面，并入规划用遮挡模型（但**不**作为新的待扫目标） |
| **Bfrontier** | 探索基线。收益改为"预计新揭示多少未确认栅格"，其余（平台、传感器、预算、安全约束、路径规划、成本折算）与本方法完全相同 |

（更早实验中还有 B0_random 随机、B1_patent 母专利原式、B5_occ_rng 仅遮挡+量程、
Bdisp_maxmin 无信息最大离散、Bbim_offline 纯 BIM 离线覆盖规划。本轮 E7/E8 未用。）

**B10 与 B11 只差一个开关**，所以 `B11 − B10` 这个差值可以干净地归因于在线环境更新。

## 六、五个先验强度档（E7 的自变量）

这是 E7 唯一变化的东西。**看懂这张表，E7 的结论就看懂了。**

| 档 | 遮挡侧（看得见什么） | 占据侧（能走到哪） | 这一档单独回答什么 |
|---|---|---|---|
| **LEGACY** | 完整参考模型 | 完整模型栅格化 | 原方案，参照基准 |
| **P100** | 完整参考模型 | **由观测建立** | 「把'哪里能走'改成观测驱动，要付多少代价」 |
| **P75** | 目标 ＋ 随机保留 75% 环境构件 | 由观测建立 | 遮挡先验减弱的代价 |
| **P50** | 目标 ＋ 随机保留 50% 环境构件 | 由观测建立 | 同上 |
| **P0** | **只有目标表面** | 由观测建立 | 同上，最弱：模型只说要检查什么 |

两点务必注意：

1. **`LEGACY → P100` 与 `P100 → P0` 必须分开看。** 它们是两条不同的信息通路
   （**能不能走** / **看不看得见**）。混在一档里，读不出是哪一条在起作用。
2. **环境构件按对象整取整舍**，不按三角面随机删 —— 随机删三角面会留下"半张皮"，
   物理上无意义。目标构件与地面在任何档都保留。

## 七、指标详解

以下 `↑` 表示越大越好，`↓` 表示越小越好。

### 7.1 任务完成度

#### `awc_gap_recovery` 面积加权缺口恢复率 ↑

- **定义**：所有缺口表面分块中，被本轮补充扫描补上的比例，**按分块面积加权**。
- **范围**：0–1。
- **不代表**：不代表"资产被检查到的比例"。一段大面积母线的分块面积可能是一台断路器
  的几十倍，所以这个指标会被大而平的表面主导。

#### `asset_recovery` 资产级恢复率 ↑

- **定义**：以**构件**为单位统计恢复情况，不按面积加权。
- **为什么两个都要报**：二者分歧最能说明问题。E8 中 frontier 的 awc 是 0.797 而
  asset 只有 0.523 —— 它按面积分配观测，把大而空的区域也扫了，但没有把设备扫全。

#### `crit_recall` 关键设备召回 ↑

- **定义**：重要度较高的设备（隔离开关、CT/PT 等，E_i = 0.8）中被补上的比例。

#### `dens_ok` 密度达标率 ↑ / `dens_ok_vs_full` ↑

- `dens_ok`：点密度达到要求的分块比例。
- `dens_ok_vs_full`：相对于"完整参考站集"所能达到的密度达标率之**比值**。
  **可以大于 1**（表示比参考站集做得还好），不是错误。

### 7.2 成本

| 指标 | 含义 | 说明 |
|---|---|---|
| `path_len_m` ↓ | 移动平台走过的路径总长（米） | **预算口径是纯路径长度**。单站架设耗时只在贪心的性价比里折算成等效距离，不占这个预算 |
| `n_stations` ↓ | 实际执行的补充扫描站数 | 上限 6 |
| `ig_per_m` ↑ | 单位路径长度的信息增益 | 与本方法内部成本函数同构，**不能作为独立确认** |

### 7.3 预测质量（本轮新增，E7/E8 的关键证据）

这三个量在**每执行一站时**测量，用的是**规划器当时实际据以决策的那个遮挡模型**，
在该站观测并入之前计算。也就是说，它们衡量的是"规划器当时以为看得见的，和实际
看得见的，差多少"。

#### `vis_mae` 可见性预测平均绝对误差 ↓

`mean( |预测可见比例 − 实际可见比例| )`，对全部目标分块取平均。双向。

#### `vis_over` 可见性**单向高估** ↓ ← **最重要的一个**

`mean( max(预测 − 实际, 0) )`。

- **为什么单独看单向**：本发明针对的错误是**单向的** —— 模型里没有的物体只会挡住
  真实扫描，不会挡住预测。把它和低估的一侧混在 MAE 里，会被稀释。
- 实测中 B10 的 `vis_mae` 与 `vis_over` 数值相同，说明误差**几乎全部是高估**。

#### `invalid_view_frac` 无效视点占比 ↓

预测明确可见（≥0.5）而实际几乎全被挡住（<0.1）的目标分块占比。
这是**"白跑一趟"的直接计数口径** —— 规划器以为能测到，去了发现被挡住。

### 7.4 建图进度

#### `mplan_known_ratio` 规划环境模型已确认比例 ↑

非"未确认"状态的栅格占全部栅格的比例。

- **这是探索类方法的目标函数**，不是本方法的。
- LEGACY 档恒为 1.000（规划器一开始就有完整地图，按定义已知率为 1）。

### 7.5 终止原因 `stop_reason`

| 值 | 含义 |
|---|---|
| `rounds` | 正常用满全部轮次 ← **健康状态** |
| `stations` | 触及站数上限 |
| `length` | 路径预算耗尽 |
| `no_candidate` | **候选池空了** ← 需要追查。本轮曾因缺陷大量出现，修复后 240 次运行中为 0 |

## 八、统计方法

### 什么是一个"配对"

一个 **(场景, 种子)** 组合。E7 用 3 类场景 × 8 个随机种子 = **24 组配对**。
比较两个方法时，是在**同一个场景、同一个随机种子**下比，消除场景难度的影响。

### 配对置换检验（paired permutation test）

- **做什么**：把 24 组差值的符号随机翻转，看"实际观察到的平均差"在随机翻转的分布里
  有多极端。
- **p 值的含义**：若两个方法真的没差别，"看到这么大的差"的概率。**p 小 = 差别不像是
  偶然**。
- **分辨率下限**：m 组配对能给出的最小 p 是 `2/2^m`。24 组时是 1.2×10⁻⁷，足够。

### Holm 校正与 `p_holm`

同时做多个检验时，"总有一个碰巧显著"的概率会累积。Holm 校正逐步抬高门槛来抵消。

- **`p_holm` 是校正后的 p 值**，比原始 p 大或相等。本包中报告的显著性一律以它为准。
- **`p_holm = 1.0000` 不等于"两者相同"**，只等于"这批数据没能显示出差别"。

### bootstrap 95% 置信区间

对差值重采样 10000 次得到的区间。**若区间不跨 0，方向是稳的。**

### 怎么读一行结果

表中一行形如：先验档 `P0`，指标 `asset_recovery`，差值 `+0.092`，
95% 置信区间 `[+0.042, +0.146]`，`p_holm` = `0.0117`。

读作：在 P0 档，B11 的资产恢复率比 B10 平均高 **0.092**；重采样 95% 的情况下这个
差在 +0.042 到 +0.146 之间（**不跨 0，方向稳**）；多重比较校正后 p = **0.0117**
（**显著**）。

## 九、可复现性与工程约定

| 术语 | 含义 |
|---|---|
| **`run.json`** | 一次运行的全部记录：逐轮指标轨迹、最终指标、配置哈希、**产出它的 git commit** |
| **commit 守卫** | 断点续跑时若发现盘上结果产自不同 commit，直接报错退出。此机制是在**三次"版本混合结果集"事故**之后加的 |
| **`config_hash`** | 实验配置的哈希。配置变了哈希就变 |
| **逐位一致**（bit-identical） | 重跑得到的数与盘上的数在浮点位级别完全相同。本轮抽 3 格校验，全部一致 |
| **种子**（seed） | 控制场景生成与仿真随机性。同一种子必然复现同一结果 |

### Oracle leakage（"偷看答案"）

**定义**：规划器读到了真实现场**不可能提供**给它的信息。

判据不是"读没读完整模型"，而是「**作业当天，这条信息拿不拿得到**」。

- ❌ 泄漏：规划器绕开了一辆设计模型里根本查不到的施工车辆。
- ✅ 不是泄漏：仿真器用完整竣工几何生成"扫描仪实际测到什么"——那是被测量的现实本身
  （Simulator Truth），且它不进入任何规划决策。

完整清单见 `06_Oracle_Leakage_Audit.md`。

## 十、三个容易混淆的地方

### 10.1 "地图覆盖得快" ≠ "任务缺口补得好"

`mplan_known_ratio` 是探索类方法的目标；`asset_recovery` 是本方法的目标。
E8 中 frontier 在前者上**赢**、在后者上差 0.40。**两个轴必须一起报**，不得只报
对自己有利的那个。

### 10.2 "可见性误差改善" ≠ "恢复率改善"

这是**分开检验的两件事**。在线环境更新在全部五个先验档都把单向高估降到 0.002
（p_holm 全为 0.0020），但它对**恢复率**的增益只在 P0 档达到显著（p_holm 0.0117），
P100/P75/P50 三档分别为 0.47 / 0.14 / 0.09。**不得把前者的显著性挪用给后者。**

### 10.3 E7 与 E2/E5/E6 的绝对指标不可跨实验比较

本轮统一了目标集口径（厂房、围墙、杂物不再算作待扫目标，占分块数的 5.7–8.0%）。
因此 E7/E8 与更早的 E2/E5/E6 的**绝对数值**不可直接对比。**各实验内部的对照不受
影响**，且 commit 守卫会拦住把两种口径拼在一起的续跑。既有结果全部原样保留在盘上。
