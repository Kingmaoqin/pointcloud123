## 核查一：S7a 的真实比较基准

### 1.1 代码事实

`UnmodeledOccluders.__init__` 把传入的三角网建成一个只用于**求距离**的
`RaycastingScene`（`self._dist_scene`）。判定在 `update()` 中：

```python
pts = pts[pts[:, 2] > self.z_min]                 # z_min = 0.35 m
d   = self._dist_scene.compute_distance(pts)
far = pts[d > self.eps]                           # eps = 0.25 m
keys = np.floor(far / self.voxel)                 # voxel = 0.40 m
self.cells.update(map(tuple, keys))               # 累积到集合
```

基准网格由 `run_episode` 传入 **[A]**：

```python
base = (world.ref_tris if world.ref_tris is not None else world.scene.bim_tri_mask())
disc = UnmodeledOccluders(world.scene.vertices, world.scene.triangles[base],
                          world.tri_to_patch[base], seed=cfg.seed)
```

而 `world.ref_tris = bim_tri_mask() & prior_tri_mask(env_prior_frac, prior_seed)`。

> **关键事实：基准不是"仅 M_ref 目标表面"，而是"该先验档实际给出的全部几何"** ——
> 目标表面 ＋ 地面 ＋ 该档保留的那部分非目标环境构件。**[A]**
>
> 也就是说，基准恰好等于 `plan_oracle` 的**初始**内容，即 M_plan 遮挡侧的初始状态。

### 1.2 回答指导 §7.1 的问题

> 在 P75/P50/P100 中，一个已作为环境先验存在于 M_plan⁽⁰⁾ 中的非目标环境构件
> （如厂房、围墙），在新扫描后是否会再次被 S7a 判定为"新发现几何"？

**不会。** 依据两条：

**(a) 判据层面 [A]**：该构件的三角面在 `_dist_scene` 中，其自身表面上的回波点到该
场景的距离约等于测距噪声（σ_r = 0.005 m），远小于 `eps = 0.25 m`，因此被
`far = pts[d > eps]` 滤除，不进入体素集合。

**(b) 实测层面 [A]**：S/low seed0，`n_temp=6`，初始三站后按体素归属统计——

| 先验档 | 先验中保留的非目标环境构件 | 发现体素归属 |
|---|---|---|
| P100 | 7 个（全部保留） | 仅 `temp_obstacle`（模型中不存在者）700 体素 |
| P50 | 4 个 | 不在先验中的 `building` 866 ＋ `fence` 602；`temp_obstacle` 700 |
| P0 | 0 个 | `building` 1221 ＋ `fence` 1651 ＋ `temp_obstacle` 700 |

P100 档**只发现了设计模型中根本不存在的临时占位物**，厂房与围墙一个体素都没有被
重复发现。

### 1.3 一处需要说明的表象

上述统计中，另有少量体素（arrester 23、disconnector 10、transformer 21）被归到
**先验中就有**的目标构件上。这是**归属统计方法的误差，不是重复发现** **[A]**：

- 归属用的是"构件包围盒 ± 0.4 m"，与邻近物体重叠时会误计；
- 更直接的证据：把全部 2114 个 P50 体素中心到先验网格求距离，**最小值 0.144 m**。
  判据 `d > 0.25` 作用于**点**，而体素中心相对其构成点最多偏离
  `voxel·√3/2 = 0.346 m`，故体素中心距离可以小于 0.25 m 而其构成点并不小于。
  0.144 ≥ 0.25 − 0.346 成立，与判据完全自洽。

**没有任何位于先验几何上的点被判为新发现。**

### 1.4 基准是"初始先验"而非"当前 M_plan"

`_dist_scene` 在构造时固定，**已发现的体素不会被加回基准** **[A]**。因此同一物体的
回波在后续轮次仍会被判为 `d > eps`，再次体素化。

**但结果等价**：`self.cells` 是集合，同一批点二次并入实测新增 **0** 个体素
（首次 1823，二次 0）**[A]**。落在相邻新体素上的点则会被正确加入——那正是"把该物体
补全"的应有行为。

### 1.5 结论与处理

判定为**指导 §7.3 的情况 A**：不会重复发现。**不需要修改代码。**

但现有文档中"发现当前 M_plan 尚未记录的占据几何"这一措辞，与代码的实际判据
（对**初始先验几何**求距离）并不逐字对应，虽然结果等价。Phase F 统一改为与代码
逐字一致的表述：

> **S7a：识别当前规划环境模型遮挡侧初始内容所未描述的现场占据几何，并将其并入
> 规划环境模型的遮挡侧；该几何不作为新的待扫描目标。**

新增测试 `test_known_prior_environment_is_not_rediscovered` 锁定该行为。

## 核查二：三维射线 → 二维 FREE 的物理含义

### 2.1 代码事实：逐条回答指导 §8.1

`PlanningEnvGrid.integrate_scan(origin, points, z_lo=0.20, z_hi=1.80)`：

```python
band = (pts[:,2] >= z_lo) & (pts[:,2] <= z_hi)
self._carve_free(o, pts)                      # ← 传入的是全部点
ij = self._to_ij_array(pts[band])             # ← 只有带内点标占据
self.state[ij[:,0], ij[:,1]] = OCCUPIED
```

| 指导的问题 | 代码事实 [A] |
|---|---|
| 1. 是否所有回波点的射线都用于 FREE carving？ | **是。** `_carve_free(o, pts)` 传入的是**全部**点，未按高度过滤 |
| 2. 是否只使用某高度区间的射线？ | **否。** 高度带 `[0.20, 1.80]` **只用于标记 OCCUPIED**，不约束 carving |
| 3. 是否考虑射线高度随距离变化？ | **否。** `_carve_free` 只用 XY：`d = pts[:,:2] − origin[:2]`，沿该二维线段等距取样 |
| 4. 是否只按 XY 投影把整条射线经过的栅格标 FREE？ | **是**，且末端留一格不标（`back = 1 − res/rng`），避免把终点障碍抹成自由 |
| 5. 是否有 ground/floor reference？ | **无显式地面参考。** `z_lo=0.20` 仅用于占据侧；`Z_MIN=0.35` 是遮挡发现模块的另一参数 |
| 6. 是否考虑平台实际占用高度或扫掠体积？ | **否。** 平台尺寸只在事后以半径 `r_robot=0.6 m` 作欧氏距离变换膨胀 |
| 7. OCCUPIED 与 FREE 冲突时谁优先？ | **OCCUPIED 优先。** 同一站内 carving 先执行、占据后覆盖；跨站由 `np.where(cur==OCCUPIED, OCCUPIED, FREE)` 保证已确认占据不被射线抹回 |

### 2.2 因此现有解释确实过强

现有文档写"激光从站位到回波点沿途没有命中，因此沿途区域**被证明可通行**"。

按上表，这在物理上不成立 **[B]**：三脚架高度 `TRIPOD_Z = 2.0 m`，一条射线完全可以
从一个 1.0 m 高的障碍**上方**掠过并击中远处地面，而该障碍位于平台通行高度带
`[0.20, 1.80]` 之内。此时沿途栅格会被标 FREE。

**该错误的自限机制** [B]：同一物体通常也会在带内产生回波，从而被标 OCCUPIED；而
OCCUPIED 优先于 FREE，且不被后续射线抹回。只有"在任何一站都没有产生带内回波"的
物体才会长期停留在错误的 FREE 状态。

### 2.3 实测该近似的量级

S/low seed0，P0，初始三站后，把 M_plan 的可通行格与竣工实景可通行格逐格比对 **[A]**：

| | 格数 | 占比 |
|---|---|---|
| M_plan 认为可通行 | 10 364 | — |
| 竣工实景确实可通行 | 11 925 | — |
| **误判为可走**（M_plan 可走、实景不可走） | **146** | 占 M_plan 可通行的 **1.41%** |
| 漏判为不可走（实景可走、M_plan 不可走） | 1 707 | 占实景可通行的 **14.31%** |

被误判为可走的 146 格，其三态**全部为 FREE**（UNKNOWN 0、OCCUPIED 0），确认误差
来源正是二维 carving，而非"未知当作可走"。

> 两个方向的量级相差约 10 倍：**该实现整体是保守的**（漏判为不可走 14.31%，
> 远大于误判为可走 1.41%）。

### 2.4 结论与处理

判定为**指导 §8.3 的"模型简化"，不是逻辑错误**：

- 误判方向的比例为 1.41%，且被"占据优先"机制自限；
- 整体偏保守，不会系统性地让规划器穿越障碍；
- 240 次 E7 运行全部正常收敛，无一因路径不可用而失败。

**不需要修改代码。** 按指导 §8.2 改文字，并明确记为实施方式假设：

> 将射线穿越区域作为自由空间的观测证据，并在当前二维栅格实施方式下据此更新
> FREE 状态。该状态是**基于二维投影的规划近似**，最终仍受平台半径收缩、已确认占据
> 优先以及安全禁入区约束。

## 四、本轮由核查衍生的一处文档错误（与代码不符，必须改）

核查指标代码时另发现一处**现有文档写错**的地方 **[A]**：

`00B_术语与指标详解_FINAL.md` 把 `awc_gap_recovery` 写成「按分块**面积**加权」。
代码实际权重为：

```python
w = area * (1 + lambda_e * imp)          # lambda_e = 1.0
```

即 **面积 × (1 ＋ λ_E·工程重要度)**，不是纯面积。该错误不影响任何实验数字，但影响
读者对指标的理解，Phase E 一并修正。
